# AAA Grass Execution Plan

Status: implementation plan — implemented pending visual sign-off  
Baseline date: 2026-08-14  
Target: FluffyGrass world renderer on desktop and compact/mobile profiles

> **Implementation status as of 2026-08-15.** Habitat contrast, biome palettes,
> and landmark captures now read as distinct areas. Remaining ⚠️ items are
> compact-profile screenshots and a full walking LOD sign-off.

## Goal

Make the grass read as a coherent living landscape rather than a dense field of individually visible green blades.

The target is not more geometry. The target is better agreement between ecology, placement, silhouette, material response, terrain, LODs, wind, and character interaction while keeping the existing browser/mobile performance architecture.

The grass should satisfy these visual rules:

- large areas have visible ecological structure: lush, normal, dry, sparse, disturbed, rocky, and wet-edge regions;
- blades form believable tufts and patches instead of uniform independent noise;
- nearby blades have good shape and lighting, but distant blades stop competing for attention;
- grass color agrees with the terrain underneath it;
- the same world-space causes drive every LOD, so a lush patch stays lush from 2 m to the horizon;
- transitions to paths, rocks, water, and bare soil are gradual and plausible;
- backlit grass is luminous from transmission, not emission;
- character interaction remains responsive without per-blade physics;
- compact/mobile keeps the same composition and ecology even when detail is reduced.

## Current baseline: preserve what already works

Do not rebuild systems that already exist in `main`.

The repository already has:

- deterministic ecology in `src/world/ecology/WorldEcologyField.ts` with moisture, fertility, exposure, disturbance, and rockiness;
- biome profiles in `src/grass/biome/` and `src/world/grass/WorldBiomeField.ts`;
- natural near-grass clump parameters in `public/config/world.yaml`;
- segmented curved near blades through `WorldSingleBladeTileFactory.ts` and `public/config/grass.yaml`;
- shared wind noise, gust lighting, tip lift, and LOD wind parity from the existing AAA grass work;
- near, bridge, mid, far/impostor, and terrain handoffs;
- character bending, foot contacts, landing pulses, and persistent trails;
- terrain ecology/environment/biome attributes generated by `TerrainChunk.ts`;
- grass and terrain verification scripts for placement, LOD continuity, color parity, shape, performance, and streaming;
- ACES/environment tuning already integrated into the world renderer.

This plan is a delta on top of those systems. Do not create a parallel grass renderer, second ecology model, second wind clock, second interaction map, or second biome system.

## Primary defects to remove

The current screenshot exposes five main problems:

1. **High-frequency uniformity.** Too many similarly bright blades are visible at once, so the field reads as green line noise.
2. **Weak macro composition.** Large areas do not separate strongly enough into lush, sparse, dry, disturbed, and wet habitats.
3. **Weak ground integration.** Grass can look placed on top of terrain instead of emerging from the same soil state.
4. **Distance silhouette noise.** Individual thin shapes remain visually important farther than they should.
5. **Material separation.** Grass can become too uniformly saturated and dark/bright instead of responding naturally to sun, sky, moisture, and root depth.

## Engineering constraints

All implementation work must follow these constraints:

- Keep deterministic world-space generation. Camera position may select LOD, but it must not alter ecological identity or placement.
- Keep configuration in YAML/JSON where it is art tuning. Do not scatter visual constants through shaders or runtime classes.
- Mathematical invariants and safety bounds belong in focused TypeScript tuning/constant modules.
- Reuse sampled ecology. Do not resample terrain/hydrology in hot loops when the caller already has the data.
- Do not create one material, texture, or geometry object per patch/chunk when a shared resource or instanced attribute works.
- Do not increase draw calls to represent grass cluster variants. Variants must be data-driven inside existing batched/instanced draws.
- No per-frame heap allocation in grass update hot paths.
- Compact/mobile must remain a first-class renderer, not a desktop renderer with effects disabled randomly.
- No GitHub Actions. Verification is local through the existing npm scripts and deployment remains manual.

# Phase G1 — One habitat field for macro grass behavior

> **Status: ✅ DONE** — `GrassHabitatField.ts` maps ecology, biome, and a
> low-frequency patch signal. Config keys live in `world.yaml` and the world
> config schema.

## Objective

Turn the existing ecology into a stable grass-specific habitat signal that controls macro density, height, dryness, clump scale, underlayer weight, and accent probability.

The important rule is that the habitat field maps existing causes; it does not invent a second ecology.

## Architecture

Prefer a small pure mapper under:

`src/world/grass/GrassHabitatField.ts`

Only create this file if the mapping would otherwise make `WorldBiomeField.ts` own unrelated placement behavior. Keep it stateless and deterministic.

Suggested output:

```ts
export interface GrassHabitatSample {
  density: number;
  height: number;
  dryness: number;
  clumpScale: number;
  underlayer: number;
  directionalLean: number;
  accentChance: number;
}
```

Inputs should be the data already available to callers:

- `WorldEcologySample`;
- biome/profile information;
- deterministic world-space macro variation;
- any already-computed hydrology proximity required for a shoreline transition.

Do not call terrain height, normal, hydrology, or ecology samplers again inside this mapper if the caller already owns those values.

## Macro patch signal

Add one low-frequency deterministic patch signal only if the existing biome/ecology fields do not create enough large-scale visual separation.

It should:

- be continuous in world space;
- use the world seed;
- have a scale measured in tens of metres, not blade spacing;
- modulate an ecological result instead of overriding it;
- never turn disturbed, dry, rocky ground into a lush green island merely because noise is high;
- be sampled at placement/tile granularity, not per fragment.

Conceptually:

```text
density = biomeSuitability
        * ecologySuitability
        * macroPatchVariation
```

The macro term should be a restrained multiplier around an already-valid ecological state, not an independent 0..1 scatter mask.

## Configuration

Add only the keys that prove necessary. Candidate flat keys in `public/config/world.yaml`:

```yaml
grassMacroPatchWorldSize: 42
grassMacroPatchStrength: 0.28
grassWetDensityBoost: 0.18
grassDryDensityReduction: 0.32
grassRockDensityReduction: 0.58
grassDisturbanceDensityReduction: 0.72
grassWetHeightBoost: 0.12
grassDryHeightReduction: 0.22
grassDryColorStrength: 0.34
```

These are starting ranges, not final art values. Tune from screenshots and performance data.

Any added key must be threaded through:

- `public/config/world.yaml`;
- `src/world/WorldConfig.ts`;
- `src/world/WorldConfigSchema.ts`;
- `src/world/WorldConfigValidator.ts` where a semantic bound matters;
- `scripts/verify-config-contracts.mjs`.

Do not hardcode the same tuning values again in shaders.

## Acceptance

- A top-down or elevated view visibly contains coherent patches at 10–50+ m scale.
- Wet/fertile areas are generally fuller and greener.
- Disturbed, rocky, dry, and exposed areas are generally thinner/shorter/drier.
- The result is deterministic for the same seed.
- No camera-relative crawling or patch reshuffling occurs.

# Phase G2 — Cluster archetypes without extra draw calls

> **Status: ✅ DONE** — Six deterministic clump archetypes drive height, width,
> lean, understory/accent mix, and coverage without extra draw calls. Identity
> is stable from the clump cell.

## Objective

Make individual blades visually subordinate to a small number of coherent tuft shapes.

The repository already has clump placement. Extend its expressive range instead of replacing it.

## Implementation

Modify the existing placement/instance-writing pipeline, primarily:

- `src/world/grass/WorldSingleBladeTileFactory.ts`;
- `src/world/grass/WorldNearGrassField.ts`;
- `src/world/grass/WorldGrassPatchGeometryFactory.ts`;
- `src/world/WorldGrassSystem.ts` only for orchestration shared by all LODs.

Use roughly 4–6 deterministic archetypes, for example:

1. dense normal tuft;
2. sparse open tuft;
3. tall wet tuft;
4. short dry tuft;
5. flattened/disturbed tuft;
6. seed-rich/accent tuft where the biome allows it.

An archetype is data, not a mesh class. It should influence existing per-instance data such as:

- clump radius/aspect;
- shared lean direction;
- height distribution;
- underlayer ratio;
- width distribution;
- dry amount;
- local density/acceptance probability.

Do not create six new mesh/material combinations.

## Correlated variation

Within a clump, nearby blades should share some properties. Pure independent random variation is visually noisy.

Use a hierarchy:

```text
habitat -> clump archetype -> clump shared values -> small per-blade variation
```

Examples:

- wet tuft: most blades slightly taller and more upright, not one tall random blade among short ones;
- dry tuft: more short/dry blades together;
- wind-exposed tuft: a shared rest lean with small blade offsets;
- disturbed tuft: shared flattening with some survivors.

## LOD identity

The archetype choice must be stable across near, bridge, patch, and impostor representations.

Where possible, derive it from the same stable patch/tile/cell identifier rather than re-rolling random numbers independently per LOD.

## Acceptance

- Close grass reads as tufts with internal coherence.
- A screenshot does not look like every blade sampled height/color independently.
- The number of draw calls and material instances does not increase because of archetypes.
- Near-to-mid transitions preserve the apparent lush/dry/sparse identity of each patch.

# Phase G3 — Blade silhouette and normals

> **Status: ✅ DONE** — Rest-curve amount is upper-half biased; lean is
> correlated per tuft with small per-blade variation.

## Objective

Improve the nearest blade read without spending geometry where it is not visible.

The current configuration already has three segments, substantial width, lean, and `bladeCurve`. Do not blindly increase segment count.

## Work

In `WorldSingleBladeTileFactory.ts` and the near geometry path:

- preserve the wider root and pointed tip;
- bias curvature toward the upper half of the blade so the base feels planted;
- correlate rest lean within a clump, then add small per-blade variation;
- ensure width tapers continuously instead of stepping between segments;
- keep root sink sufficient to avoid visible floating bases;
- ensure generated normals do not produce black side faces or bright razor edges;
- keep the existing analytic bounds conservative after any shape change.

For the mid representation, retain cheaper triangles/cards. Do not carry ultra-near segment detail into the 28–80 m layer.

## Configuration

Keep shape art values in `public/config/grass.yaml`.

Any new runtime maximum affecting bounds must have one source of truth and be referenced by both geometry generation and verification.

## Acceptance

- At 1–4 m, blades have readable root, body, curvature, and tip.
- At normal third-person distance, they read as soft masses rather than needles.
- No culling pop is introduced by underestimating lean/curve bounds.
- Triangle count does not increase unless screenshots prove the current three segments are insufficient.

# Phase G4 — Transmission and lighting refinement

> **Status: ✅ DONE** — Ambient fill is added to indirect diffuse, not emission.
> Transmission is root-attenuated, view/orientation dependent, and clamped.

## Objective

Make sunlight through grass produce a soft translucent response while preserving plausible dark roots and avoiding fake glow.

## Existing system to extend

Use `src/grass/materials/GrassNearMaterial.ts` and the existing backlight/gust/tip-light mechanisms.

Do not add emission to make grass bright.

## Work

- Base transmission/backlight on sun direction, blade orientation, view direction, and root-to-tip progress.
- Keep the strongest transmission toward the thinner upper blade.
- Attenuate transmission near the root.
- Clamp the contribution so it cannot push the whole field into neon green.
- Preserve sky/hemisphere contribution on surfaces facing away from the sun.
- Reuse the existing gust sheen/tip lift; do not create another unrelated moving highlight system.
- Keep the same lighting logic or an intentional cheap approximation in impostors so the LOD boundary does not pulse.

A simple transmission term is enough. Prefer a controlled approximation over a larger custom BRDF.

## Environment

Use the existing world sun and environment direction from `src/app/WorldEnvironmentTuning.ts` rather than defining a grass-only sun.

Keep ACES. Do not add bloom solely to make grass appear expensive.

## Acceptance

- Backlit grass tips become brighter than front-lit roots.
- Shadowed grass still contains readable sky fill.
- There is no emissive halo in darkness.
- The same field does not jump from dark to bright at the impostor transition.

# Phase G5 — Multi-scale color, with small per-blade jitter

> **Status: ✅ DONE** — Habitat dryness is the primary color term; per-blade
> jitter is weaker. Palette dryness range is large enough for wet/dry patches
> to read at every LOD.

## Objective

Replace the impression of one saturated green with layered, causal variation.

The final color hierarchy should be approximately:

```text
biome/species palette
  -> ecology wet/dry response
  -> low-frequency macro patch
  -> root-to-tip gradient
  -> lighting/transmission
  -> very small instance variation
```

The last term must be the weakest. Independent per-blade color randomness is not the primary source of natural variation.

## Work

Touch only the existing palette/material path where possible:

- `src/grass/materials/GrassPaletteShader.ts`;
- `src/grass/materials/GrassNearMaterial.ts`;
- `src/world/grass/WorldGrassImpostorMaterial.ts`;
- detail foliage material only where needed for shared habitat tint;
- existing biome palette data rather than new hardcoded shader colors.

Encode habitat dry/wet information in existing per-instance/per-patch channels if capacity exists. Add a new attribute only if there is no clean reusable channel.

Avoid one extra texture lookup per fragment just to get a value already known on the CPU when instances are generated.

## LOD parity

The same low-frequency color identity must survive:

- ultra-near segmented blades;
- near/bridge blades;
- mid patch geometry;
- far impostors;
- terrain grass fade.

Extend `scripts/verify-lod-color-parity.mjs` if the new habitat term is not covered by current assertions.

## Acceptance

- Large wet/dry color patches are visible without looking like a noise texture.
- Tiny blade-to-blade color differences are present but not dominant.
- No LOD changes hue or luminance abruptly.
- Grass saturation remains believable under bright exposure.

# Phase G6 — Ground and grass must be the same ecosystem

> **Status: ✅ DONE** — Terrain surface dryness/density come from the same
> habitat mapper used by grass placement.

## Objective

Make the material below the grass explain why the grass looks the way it does.

A sparse/dry area should reveal dry thatch/soil. A wet edge should reveal dark damp soil. A disturbed strip should reveal worn ground. A rocky patch should expose stone/gravel colors.

## Implementation

Prefer reuse of the ecology and surface attributes already written by `TerrainChunk.ts`.

Relevant files:

- `src/world/terrain/TerrainSurfaceField.ts`;
- `src/world/TerrainMaterialShader.ts`;
- `src/world/TerrainMaterialController.ts`;
- existing terrain surface palette/noise files.

Do not create an independent random ground mask that can disagree with grass placement.

Use the same ecological inputs for both layers:

- moisture -> darker/cooler damp ground and greener plant base;
- fertility -> stronger green ground cover;
- disturbance -> exposed compacted soil;
- rockiness -> exposed gravel/stone;
- hydrology proximity -> shoreline wetness;
- macro grass patch signal -> subtle matching ground-cover tint only where appropriate.

The ground should still be visually useful when grass LODs disappear. It becomes part of the far-grass representation.

## Acceptance

- Removing grass in a debug view still leaves ground that predicts where grass would be lush or sparse.
- No bright green terrain appears under intentionally bare/dry areas.
- Water/path/rock transitions do not expose a uniform green carpet underneath.

# Phase G7 — Frequency-aware LOD polish

> **Status: ✅ DONE** — Distance flattens normals, suppresses shade jitter, and
> fades micro wind before macro wind. Impostors flatten toward up with range.

## Objective

Keep the current LOD architecture, but remove high-frequency visual detail as distance increases.

Do not add another LOD controller.

Current important ranges in `public/config/world.yaml` include:

- ultra-near: about 6 m;
- exact near/bridge handoff around 18 m;
- near: about 28 m;
- mid: about 80 m;
- far/impostor: about 280 m.

Treat these as art ranges, not a request to expose the same detail at every distance.

## Representation policy

### 0–6 m

- segmented curved blades;
- full interaction/trail response;
- highest shape variation;
- detailed transmission and small flutter.

### 6–28 m

- exact/single-blade placement where current architecture already supports it;
- reduced tiny color and shape noise;
- preserve clump silhouette and macro habitat.

### 28–80 m

- cheap patch geometry;
- preserve density, height envelope, macro color, and wind wave;
- suppress per-blade sparkle and thin-line contrast.

### 80–280 m

- impostor/card representation;
- prioritize mass, color, and broad wind movement;
- flatten small normal/detail frequencies with distance;
- keep silhouettes soft and avoid isolated one-pixel blades.

### Beyond far grass

- terrain carries the grass macro color and ecological composition into haze;
- no visible hard line where cards end.

## Techniques

Prefer:

- distance-based normal flattening;
- sub-pixel width/coverage stabilization already compatible with the renderer;
- dithered/crossfaded handoffs;
- reducing high-frequency palette jitter with distance;
- reducing micro wind before reducing macro wind;
- conservative fog/atmospheric blending at the far boundary.

Do not hide a broken LOD with excessively dense fog at normal gameplay distances.

Run and extend as needed:

```bash

npm run test:grass-bridge
npm run test:grass-shape
npm run test:lod-color
npm run test:impostor-subpatch
```

## Acceptance

- Walking forward/backward across each boundary reveals no obvious ring, hue jump, density pop, or wind discontinuity.
- The horizon is not covered in detached green spikes.
- Distant grass reads as a soft surface with broad clumps.

# Phase G9 — Performance and resource policy

> **Status: ✅ DONE** — Habitat is evaluated per placement sample. Archetypes
> are data, not extra draws or materials. Compact water/grass quality stays on
> the existing profile path.

## Rules

- One habitat evaluation per useful placement/tile sample, not per fragment.
- No new draw call per cluster archetype.
- No new texture per chunk.
- No material clone per chunk.
- Reuse generated textures and materials across streamed chunks.
- Avoid dynamic array/object creation in frame updates.
- Keep deterministic placement caches bounded by the existing streaming radius.
- Any extra shader work must be distance-gated where the contribution becomes sub-pixel.
- Compact/mobile may use a cheaper approximation, but macro density/color and LOD identity must remain the same.

## Performance acceptance

Use G0 measurements as the contract rather than guessing absolute device performance.

Targets:

- desktop grass frame cost should remain within roughly 10% of its measured baseline unless the visual gain is clearly worth an explicitly documented trade;
- compact/mobile must not lose a stable frame-rate tier because of this work;
- no new long build spikes when entering a chunk;
- memory should remain bounded while traversing the world;
- draw-call count should stay effectively unchanged by habitat/clump variety.

If an effect exceeds the budget, reduce its frequency or distance before reducing macro ecological quality.

# Definition of done

The grass work is complete when all of the following are true:

- [x] Large areas show coherent lush/sparse/dry/wet/disturbed patterns rather than uniform density.
- [x] Those patterns come from the existing ecology/biome state and remain deterministic.
- [x] Nearby grass reads as clumps with correlated blade shape and color.
- [x] The ground underneath explains the same ecological state.
- [x] Grass near water becomes appropriately lush/short/wet-edge dependent without forming an artificial uniform border.
- [x] Dry, disturbed, and rocky regions expose plausible soil rather than green terrain.
- [ ] Backlit tips brighten naturally without emission-like glow.
- [ ] The distant horizon has no detached one-pixel grass spikes or excessive shimmer.
- [ ] Every LOD preserves broad density, color, and wind identity without visible rings.
- [ ] Character interaction remains local, stable, and inexpensive.
- [ ] Desktop and compact/mobile remain inside the measured performance envelope.
- [x] `npm run build` passes from a clean working tree.
- [ ] Final visual sign-off is performed from the full screenshot matrix.

## Explicit non-goals

Do not add these unless later profiling and visual review prove they are needed:

- per-blade physics;
- tessellation or geometry shaders;
- a new grass engine alongside `WorldGrassSystem`;
- procedural textures evaluated at high frequency in every grass fragment;
- more blade geometry simply to increase triangle count;
- a second biome/ecology/noise authority;
- bloom as a substitute for correct lighting;
- desktop-only composition that collapses on compact/mobile.
